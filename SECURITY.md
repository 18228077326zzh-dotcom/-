# Security policy

Do not put API keys, customer spreadsheets, personal data, private URLs, or store credentials in a public issue.

For a vulnerability report, contact the repository owner privately when possible and include the affected project, commit, a minimal reproduction using synthetic data, and the expected impact. If private contact is unavailable, open a public issue without exploit details or sensitive data and label it `security`.

The projects are public portfolio applications. They do not provide a production SLA, bug-bounty program, multi-tenant authorization, or regulatory compliance guarantee. See each project-level `SECURITY.md` for its specific threat model and safe deployment guidance.
